## 背景（Context）

这是一个使用 Vue 3 + Vite 构建的 uTools 插件。功能通过 `public/plugin.json` 声明，渲染层通过挂载在 `window.services` 上的预加载脚本访问 Node.js 能力。现有功能包括 Claude Code 项目启动器（`ccstart`）和配置管理（`ccstartconf`）。

开发者在日常工作中经常需要执行一些记不住的常用命令，如升级 CLI 工具、查看版本、清理缓存等。新增 `ccrun` 功能提供一个命令列表界面，用户可以快速选择并在终端中执行这些命令。

## 目标 / 非目标（Goals / Non-Goals）

**目标（Goals）：**
- 提供内置常用命令列表（Claude CLI、OpenSpec、npm、git 等）
- 支持用户添加、编辑、删除自定义命令
- 快速搜索和键盘导航（方向键、回车）
- 选中命令后直接在终端中执行，无需二次确认
- 区分命令执行位置：任意位置 vs 需要在项目目录
- 通过 uTools `dbStorage` 持久化自定义命令
- 复用现有的 `launchProject` 函数启动终端并执行命令

**非目标（Non-Goals）：**
- 不在插件内执行命令并显示输出（直接在系统终端执行）
- 不解析或验证命令的正确性（由用户和系统终端负责）
- 不提供命令历史记录或执行日志
- 不替代或修改现有的项目启动器功能

## 决策（Decisions）

### 决策：命令分为内置和自定义两类
内置命令硬编码在预加载层，包含常用开发工具的操作（Claude、OpenSpec、npm、git）。用户自定义命令存储在 `utools.dbStorage` 中，支持增删改。两类命令在列表中混合展示，但内置命令不可编辑删除。
- *已考虑的替代方案*：所有命令都可编辑 —— 但内置命令是精心设计的常用操作，不应被误删或修改。

### 决策：命令执行位置标记
每个命令有 `needsProjectDir` 标记：
- `false`：可在任意位置执行（如 `npm install -g ...`）
- `true`：必须在项目目录执行（如 `git status`、`openspec status`）

执行时，如果命令需要项目目录，尝试获取最后使用的项目目录（从 ccstart 记录），如果没有则提示用户。
- *已考虑的替代方案*：每次都让用户选择项目 —— 过于繁琐；大多数情况下使用最近项目即可。

### 决策：选中后直接执行，无二次确认
用户在列表中选中命令后按回车，直接在终端中执行并关闭插件窗口，不弹出确认对话框。这符合快捷工具的使用习惯：列表本身已经清晰展示命令内容，用户选择即表示确认。
- *已考虑的替代方案*：执行前弹出确认框 —— 增加操作步骤，降低效率；危险命令由用户自行控制是否添加。

### 决策：复用现有的 launchProject 函数
命令执行复用 `launchProject(cwd, command, options)` 函数，该函数已实现跨平台终端启动和命令执行逻辑，无需重复开发。只需传入工作目录和命令字符串即可。
- *已考虑的替代方案*：单独实现命令执行逻辑 —— 代码重复，且需要重新处理跨平台兼容性。

### 决策：独立的管理界面（ccrun-manage）
命令的添加、编辑、删除通过独立的 `管理命令` 功能入口进行，不在命令列表界面中嵌入管理功能。这保持了 `ccrun` 界面的简洁和专注。
- *已考虑的替代方案*：在列表中右键或长按编辑 —— uTools 插件的交互限制较多，独立界面更清晰。

### 决策：使用 uTools 的 setSubInput 实现搜索
利用 uTools 原生的 `setSubInput` API 接管输入框，实现实时搜索过滤。这符合 uTools 用户的使用习惯，无需自己实现搜索框 UI。

## 风险 / 权衡（Risks / Trade-offs）

- **命令执行失败用户可能不清楚原因** → 缓解：使用 `launchProject` 返回的错误信息通过 `utools.showNotification` 提示用户。
- **需要项目目录的命令在没有项目时无法执行** → 缓解：清晰标记（📂图标），执行失败时提示用户先使用 ccstart 启动项目。
- **用户可能添加危险命令（如 `rm -rf`）** → 缓解：这是用户自己的选择，插件不做限制；提供描述字段让用户记录命令用途。
- **内置命令列表可能不符合所有用户需求** → 缓解：提供自定义命令功能，用户可以添加自己的常用命令。

## 迁移方案（Migration Plan）

纯增量变更 —— 无需迁移。新增的 `ccrun` 与 `ccrun-manage` 功能独立于既有功能。回滚只需移除这两个功能项、视图组件、`App.vue` 中的分支以及新增的预加载函数。

## 待解决问题（Open Questions）

- 内置命令列表是否需要支持国际化（中英文切换）？当前方案是硬编码中文。
- 是否需要支持命令的快捷键（如 Alt+1 执行第一个命令）？当前方案只支持方向键和回车。
- 是否需要在 ccstart 项目启动器中集成快捷入口（如 Alt+R 打开 ccrun）？当前是独立入口。
